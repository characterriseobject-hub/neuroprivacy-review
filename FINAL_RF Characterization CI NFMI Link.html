Procurement completeness & execution quality review

A governed, receive-only audit of the NFMI / public-FM characterisation bill of materials. Three passes are applied: a completeness pass (does every required capability have an owned, substitutable instrument?), an abundance-prioritisation refinement pass (what to buy first, what is redundant, what is parked), and an execution quality review (pass/fail gates G0–G8 with numeric acceptance criteria and evidence artefacts). Every instruction below is receive-only: no transmit blocks, no replay, no jamming, no active probing, and no DC bias into any coil or medical device.

Section 1

Scope, boundary conditions, and what this document adds

1.1 What this document is

This is the procurement and readiness layer that sits between the execution specification and the measurement itself. The execution specification defines what is measured; the supplementary methods HTML defines how the synthetic validation proves the analyser is correct. Neither document answers three questions that must be answered before any money is spent or any probe is placed:

  1. Completeness: for each required measurement capability, is there an owned instrument that can actually reach it, and is there a substitute if it fails?
  2. Abundance: the inventory lists six receivers, four loop-probe options and two oscilloscopes. Which of these are on the critical path, which are redundant, and which add governance burden without adding capability?
  3. Quality: what numeric result separates "the workflow ran" from "the workflow produced defensible data"?

This document supplies all three, plus the de-duplicated command sheet and the evidence manifest that a reviewer will ask for.

1.2 Boundary condition 0 — restated and enforced

Receive-only. Non-destructive. No exceptions. Nothing in this document instructs, implies, or enables transmission, replay, jamming, active probing, or the application of DC bias-tee voltage into a coil or a medical device. Where a measurement would ordinarily require an active source (probe calibration, two-tone linearity, noise figure), this review refuses to supply that method and substitutes a passive equivalent or marks the limitation explicitly. See GAP-01 and GAP-08.

1.4 How to use this document

  • Read §3 to confirm every capability is covered. Anything marked GAP or CONDITIONAL must be dispositioned in §4 before purchase.
  • Use §6 to place orders in tier order. Do not buy P2 or P3 items before P0 items are on the bench and G0–G3 have passed.
  • Use §8 and §9 as the pass/fail authority during execution. A stage that fails its gate is not "mostly done"; it is failed.

Section 2

Review method — three passes, one artefact

2.1 Pass A — Completeness (capability-first, not item-first)

The inventory was reorganised from item-first (a list of things) to capability-first (a list of jobs). For each capability the questions are: is there an owned item that reaches it; is the reach verified by a specification and not by assumption; and is there a second item that can substitute if the first fails. Capabilities with no answer become gap register entries. The output is the coverage matrix.

2.2 Pass B — Abundance prioritisation

Each item was scored on four axes and assigned a tier:

Criticality
Does the workflow stop without it? (Blocks Stage 0, A, B or C.)
Substitutability
Can another owned item perform the same function? If yes, the item drops a tier.
Governance burden
Transmit-capable hardware, or hardware that invites active probing, is penalised. The mandate is receive-only; an item that must be prevented from transmitting carries an ongoing procedural cost.
Marginal capability
Does the item enable a claim that no other item enables (absolute field level, 14-bit dynamic range, 148.5–500 kHz coverage)? If not, it is parked.
Table 2.1 — Tier definitions used in Section 6
TierMeaningPurchase rule
P0Blocking. A stage cannot be executed or cannot be trusted without it.Buy / confirm first. Nothing else proceeds.
P1Required for credible Stage C data (geometry, isolation, dynamic range, storage).Buy after P0 is on the bench and G0–G4 pass.
P2Required only for calibration-grade or absolute-level claims, or for convenience/repeatability.Buy only if the claim is actually being attempted. Otherwise defer indefinitely.
P3Redundant, marginal, or governance-burdening for this workflow.Park. Re-enter only against a written "buy only if" condition.

2.3 Pass C — Execution quality review

Each stage is converted into a gate with (i) a numeric or binary pass criterion, (ii) a named evidence artefact, and (iii) a defined failure action. Gates are sequential: a failed gate stops the run, it does not degrade it. The gate set is G0–G8.

2.4 Deliberate non-duplication

The execution specification and the supplementary methods document are not reproduced here. Where a procedure is unchanged, this document cites it and supplies only the acceptance criterion and the evidence artefact that the source documents omit. The command sheet in §10 is de-duplicated: each command appears exactly once, in execution order.

Section 4

Gap register — sixteen findings and their dispositions

Each gap is dispositioned as one of: Add (procure or specify), Method (supply the missing procedure — no purchase), Accept (document as a limitation of the claim), or Park (out of scope for this workflow).

4.1 Blocking gaps

GAP-01 · No absolute H-field calibration path ACCEPT + P2 MITIGATION

The inventory lists three loop-probe options but no calibration certificate, no antenna-factor data, and no permitted method of generating a known field. Because active field generation is forbidden by Boundary Condition 0, there is no in-house route to an absolute level. Disposition: accept. All Stage C levels are reported as relative — dBc against an in-band reference, or dB relative to the session noise floor. If an absolute claim is ever required, procure a loop probe supplied with a traceable calibration certificate (P2) and cite the certificate number in the report; do not attempt an in-house active calibration.

Affected claims: any statement of field strength in A/m or dBµA/m; any distance estimate derived from absolute level. Note that 1/r³ falloff remains available as a relative shape test (Tier 1 mechanics) even without absolute calibration.

GAP-02 · 148.5–500 kHz corridor unreachable with the primary receiver CONDITIONAL — METHOD + P3

The RTL-SDR Blog V4 floors at 500 kHz; the NESDR SMArt v5 floors at 25 MHz; the E4000 dongle floors at ~65 MHz. The execution specification's Stage C.2 lower bound of 148.5 kHz is therefore reachable only by the coupled pair E4000 + Ham It Up (+125 MHz LO), which shifts 148.5 kHz to 125.1485 MHz. Two consequences follow, and both are missing from the source documents:

  • The pair is a single capability, not two items. Adding one without the other adds nothing.
  • If the 148.5–500 kHz corridor is deprioritised, both items become pure redundancy and the pair drops to P3.

Disposition: method — record the lower bound of the actually-achieved sweep in the run log, and state explicitly whether the corridor was in scope. Procurement: P3 conditional.

GAP-03 · No geometry / positioning fixture ADD (P1)

A 1/r³ claim is meaningless without a repeatable distance. Nothing in the inventory holds the loop at a known, indexed distance from the target coil, and nothing logs the geometry. Disposition: add a non-metallic jig — nylon standoffs, a PTFE clamp, a millimetre scale on an indexed base — plus a photo log per session and a repeat protocol of n = 3 at each fixed distance. Total cost is trivial; the evidential value is not.

GAP-06 · Faraday null control has a claimed figure but no method ADD (METHOD)

">85 dB" is a vendor claim, not a measurement. Disposition: method — (i) tune to a strong, stable local carrier with the probe outside the bag and record 10 s; (ii) place the probe inside the closed bag, same tune, same gain, record 10 s; (iii) the difference between the two peak-hold levels is the achieved null. Record it in the run log. If the achieved null is below 85 dB, Stage C does not start.

GAP-07 · No per-band negative control ADD (METHOD)

A signal seen at 13.56 MHz is not evidence of anything until the same band is shown to be quiet in the absence of a target. Disposition: method — at each band in the sweep (6.78, 13.56, 27.12, 49 MHz, and each 3–15 MHz step), record a 10 s terminated-probe control (probe terminated into 50 Ω, inside the bag) and a 10 s probe-in-bag-at-distance control. Report both. A target observation is only reportable if it exceeds the per-band control by a stated margin.

GAP-08 · No passive linearity verification (transmission prohibited) ADD (METHOD)

The usual two-tone linearity test requires a transmitter and is therefore prohibited. A passive substitute exists and should be mandatory. Disposition: method — select a strong, steady ambient carrier. Record its level with 0, 10 and 20 dB of inline attenuation. The measured level change must equal the attenuator change within 0.5 dB. A deviation indicates front-end compression, ADC clipping, or an attenuator whose accuracy is not what the label claims. Run this before every Stage C session; it takes two minutes and invalidates an entire session if skipped.

4.2 Evidence and integrity gaps

GAP-09 · Two hash algorithms, one handoff METHOD

The handoff tool implements rf-two-file-sha256-v1 (SHA-256), while SigMF metadata records core:sha512. These are different digests over possibly different byte ranges. Disposition: method — record the algorithm name alongside every digest, in the manifest and in the capture JSON. Never infer one digest from the other; never re-hash a destination file and present it as provenance for the source. The provenance chain is: hash at capture → transfer → verify at analysis host → archive both digests.

GAP-10 · The pinned dependency list is referenced but not enumerated METHOD

Both source documents cite requirements-tested.txt but neither states its contents, so the pin set is unverifiable from the document alone. Disposition: method — archive the output of pip freeze and the SHA-256 of requirements-tested.txt as Stage A evidence. A run whose environment cannot be reconstructed is not reproducible.

GAP-11 · No galvanic isolation on the USB path ADD (P1)

Snap-on chokes suppress common-mode current but do not break the ground loop between a mains-powered host and the receiver. Disposition: add a USB galvanic isolator (ADUM4160 class) at P1, and operate the capture laptop on battery with the battery-isolated DHO804 where possible. See risk R-04.

GAP-12 · No connector-wear or consumables plan ADD (P1/P2)

Repeated SMA mating degrades repeatability and eventually the instrument. Disposition: add SMA F-F barrels as connector savers on the scope and receiver ports (P1), a 0.9 N·m torque wrench for repeatable mating (P2), and cable tags with calibration stickers (P1).

GAP-13 · No simultaneous scope + SDR observation path ADD (P1)

Correlating an envelope edge in the time domain with a spectral feature requires observing the same probe simultaneously. Disposition: add a 2-way 50 Ω splitter (P1). Note the consequence in the level budget: a resistive splitter costs ~3.5 dB per port, which must be added to every level reported through it.

GAP-14 · Transmit-capable hardware inside a receive-only mandate GOVERNANCE — PARK

The inventory lists HackRF One and USRP B210. Both transmit. Neither adds capability over the V4 or RSP1B for this workflow (8-bit and 12-bit respectively, versus 14-bit on the RSP1B). Disposition: park at P3. If one is ever used, the following controls are mandatory and must be recorded in the run log: signal taken from the RX port only; TX port terminated into 50 Ω; no transmit block present in any flowgraph; inline DC block fitted; TX capability not exercised at any point.

GAP-15 · UTC time discipline without a bounded uncertainty METHOD

SDR++ records UTC, but the host clock offset is never measured. Disposition: method — record the host clock offset against a reference at session start and end, and report the capture timestamp with that uncertainty. Do not silently assume the host clock is correct.

GAP-16 · No repeatability or uncertainty statement for NFMI measurements ADD (METHOD)

A single capture is an anecdote. Disposition: method — n = 3 repeats at each fixed geometry, report the spread; state explicitly that 1/r³ is used as a Tier 1 shape test and is not inverted to produce a distance measurement. Any distance claim would require GAP-01 to be closed first.

Section 7

Bench configurations — three purchase profiles

7.1 Minimum Viable Bench (MVB) — the smallest set that executes all four stages

MVB inventory: M01 DC block · M02 V4 · M03 SMArt v5 · M04 YouLoop · M05 hand-wound loop · M06 FM dipole · M07 50 Ω terminator · M08 attenuators (10 dB mandatory, plus one other) · M09 RG-316 ×2 · M10 SMA-BNC adapters · M11 ferrites · M12 Faraday bag · M13 battery laptop · M14 ≥256 GB SSD · M15 Python kit · M16 hashing tools · M17 SDR++/Gqrx · M18 DHO804 · M21 positioning jig · M26 photo log.

What it can claim: Tier 1 mechanics; synthetic analyser validation to the tolerances in Table 9.1; FM reference reception; relative NFMI carrier detection and Manchester/frame structure at the achieved bands; 1/r³ shape reproducibility.

What it cannot claim: absolute field level (GAP-01); the 148.5–500 kHz corridor (GAP-02); weak sidebands below about −50 dBc (GAP-05/C05); USB ground-loop immunity better than ferrite attenuation (GAP-11).

7.2 Reference-Grade Bench (RGB) — adds every capability the inventory can legitimately provide

What it adds: 14-bit dynamic range; simultaneous time/frequency observation; an absolute field claim route (only with the certificate); repeatable mating; formal uncertainty propagation.
