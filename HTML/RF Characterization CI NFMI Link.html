1. Boundary-condition framing: what this task is and is not

Theoretical-frontier corridor (anchored)

Near-field magnetic induction (NFMI) is an established physical layer: a localized, non-propagating magnetic field couples a transmitter coil to a receiver coil across a short gap. Cochlear-implant external processors and implanted receivers have used NFMI for power and data for decades. Manchester line coding, fixed word lengths, and framed packets are ordinary digital-communications constructs. These are the anchored mechanics.

Operational/physical corridor (bounded)

The specific device, its carrier frequency, packet structure, encryption state, telemetry behavior, and any claimed remote interaction are not established by this workflow. The 2017 talk reported a 12-bit word, 300-word packet structure, Manchester encoding, plaintext forward link, and no NVRAM. Those are historical findings from one researcher’s device and must be re-verified, not generalized. This workflow produces evidence; it does not produce a diagnosis or an attribution.

Advisor posture. Use the strongest established evidence for the measurement chain (Maxwell, Faraday, sampling theory, FFT, Manchester coding, hash-based integrity). Push the open frontier only where the data supports it (carrier search, packet framing, telemetry asymmetry). Never let an inferred narrative overwrite a null result.

4. Phase 1 — Characterize the target without touching it

Phase 1.1 — Establish the NFMI physical-layer baseline

NFMI is a magnetic near-field link. The field strength falls off steeply with distance, and a loop antenna must be placed close to the transmitter coil. A distant whip antenna is the wrong tool. The 2017 work used a hand-wound loop held against the head; that remains the correct first principle.

PropertyEstablished baselineWhat to verify, not assume
Physical layerMagnetic induction; non-propagating near fieldCarrier frequency, coil orientation, modulation depth
Line coding (reported 2017)Manchester, 12-bit words, 300-word packetsWhether the same framing exists on the current device
Forward linkExternal processor → implant: power + dataCarrier, symbol rate, preamble, packet boundaries
Reverse telemetryImplant → external: much weaker signalWhether it is detectable above noise with a high-gain, low-noise front end
Encryption stateHistorical device reported plaintextDo not generalize; current devices may differ
Boundary note. “No encryption” and “no NVRAM” are historical observations from one 1998-era device. They are not properties of all cochlear implants and are not a justification for any active test.
Phase 1.2 — Survey the spectrum with the SDR (receive-only)

Use the SDR to look for carrier energy and pulse envelopes. Do not transmit. If the SDR cannot tune the suspected NFMI band, use an upconverter or a different receiver rather than guessing. 

# Example: rtl_power sweep (receive-only)
rtl_power -f 10M:60M:100k -i 1 -e 60s survey.csv

rtl_power is a discovery tool. It does not capture complex I/Q and cannot resolve Manchester transitions. Use it only to identify candidate bands.

5. Phase 2 — Build the receive chain

Phase 2.1 — SDR and antenna choices

Discovery

Nooelec NESDR SMArTee XTR — ~65 MHz–2.3 GHz, 0.5 ppm TCXO, bias tee. Good general-purpose receiver; may not cover 10–30 MHz NFMI without an upconverter.

Low-band coverage

Nooelec Ham It Up v1.3 / Plus v2 upconverter extends coverage down to HF/LF. Or use an SDRplay RSPdx for better dynamic range at MF/HF.

Wideband / high dynamic range

HackRF One (1 MHz–6 GHz, 8-bit) for coverage; USRP B210 or similar for 12-bit dynamic range if budget and setup permit. More bits help weak reverse telemetry.

Antenna: a shielded loop or ferrite rod tuned to the carrier is preferable to a broadband whip for NFMI. Keep the loop small and close; orientation matters. For the oscilloscope path, a hand-wound air-core loop remains adequate for discovery, but a shielded loop reduces electric-field pickup.

Phase 2.2 — Oscilloscope fallback (when SDR fidelity is insufficient)

The 2017 lesson still holds: an SDR is for discovery; an oscilloscope is for raw waveform and edge timing. Use a digital scope with CSV export, at least 20 MS/s, and a high-impedance probe or a shielded loop into a differential input. Trigger on the envelope or a known preamble.

6. Phase 3 — Capture and preserve one reference recording

Phase 3.1 — Reference-capture policy

Prefer 5–10 seconds of raw complex I/Q from a known local FM broadcast station as the pipeline reference. This is not the implant link; it is a known-good signal with a published frequency, used to prove that the frequency axis, FFT scaling, and waterfall time axis are correct. The implant-link capture is a separate, later step and must not be conflated with the reference validation.

FM reference capture

  • Center frequency: published station frequency (e.g., 98.7 MHz).
  • Sample rate: ≥ 2.4 MS/s for a ~200 kHz FM channel; 2.4 MS/s is adequate.
  • Duration: 5–10 s.
  • Format: complex float32 or complex int16; record I/Q order.
  • Gain: fixed, not AGC, if the receiver supports it.

Why this reference matters

An FM broadcast signal has a known absolute frequency and a recognizable spectral shape. If the spectrum appears at the wrong offset, the frequency-axis mapping is wrong. If the waterfall time axis is wrong, the sample-rate interpretation is wrong. This catches errors before they contaminate a weaker, unknown NFMI capture.

Phase 3.2 — Metadata sidecar (SigMF or explicit JSON)

A bare IQ file is a wall of numbers. SigMF pairs .sigmf-data with a JSON .sigmf-meta that records datatype, sample rate, center frequency, captures, and annotations. If SigMF tooling is not available, use an explicit JSON sidecar with the same fields.

7. Phase 4 — Analysis: spectrum, waterfall, and decoding

Phase 4.1 — Python analysis script (raw complex I/Q)

The script below produces a centered power spectrum and a waterfall with an absolute RF frequency axis and elapsed time. It records FFT length, window, overlap, and relative dB units. It does not claim absolute amplitude calibration. 

#!/usr/bin/env python3
"""
analyze_iq.py — receive-only spectrum + waterfall for raw complex I/Q.
Usage:
  python analyze_iq.py capture.sigmf-data --fs 2400000 --fc 98700000 --fmt cf32 --nfft 4096 --out plots/
"""
import argparse, json, os, sys
import numpy as np
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

def load_iq(path, fmt):
    if fmt == "cf32":
        return np.fromfile(path, dtype=np.complex64)
    if fmt == "ci16":
        raw = np.fromfile(path, dtype=np.int16)
        return (raw[0::2] + 1j*raw[1::2]).astype(np.complex64) / 32768.0
    if fmt == "cu8":
        raw = np.fromfile(path, dtype=np.uint8)
        return ((raw[0::2].astype(np.float32)-127.5) +
                1j*(raw[1::2].astype(np.float32)-127.5)) / 128.0
    raise ValueError("fmt must be cf32, ci16, or cu8")

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("data")
    ap.add_argument("--fs", type=float, required=True, help="sample rate, I/Q pairs/s")
    ap.add_argument("--fc", type=float, required=True, help="center frequency, Hz")
    ap.add_argument("--fmt", default="cf32", choices=["cf32","ci16","cu8"])
    ap.add_argument("--nfft", type=int, default=4096)
    ap.add_argument("--overlap", type=float, default=0.5)
    ap.add_argument("--out", default="plots")
    args = ap.parse_args()

    os.makedirs(args.out, exist_ok=True)
    x = load_iq(args.data, args.fmt)
    if x.size == 0:
        sys.exit("empty capture")

    # --- Power spectrum (Welch-like average) ---
    step = int(args.nfft * (1 - args.overlap))
    if step <= 0: step = args.nfft // 2
    n_frames = max(1, (len(x) - args.nfft) // step + 1)
    window = np.hanning(args.nfft).astype(np.float32)
    psd = np.zeros(args.nfft, dtype=np.float64)
    for i in range(n_frames):
        seg = x[i*step : i*step + args.nfft] * window
        psd += np.abs(np.fft.fftshift(np.fft.fft(seg)))**2
    psd /= n_frames
    psd_db = 10*np.log10(np.maximum(psd, 1e-20))

    freqs = args.fc + np.fft.fftshift(np.fft.fftfreq(args.nfft, d=1/args.fs))

    fig, ax = plt.subplots(figsize=(11,4))
    ax.plot(freqs/1e6, psd_db, lw=0.8)
    ax.set_xlabel("RF frequency (MHz)")
    ax.set_ylabel("Relative power (dB, uncalibrated)")
    ax.set_title(f"Power spectrum — fc={args.fc/1e6:.3f} MHz, fs={args.fs/1e6:.3f} MS/s, NFFT={args.nfft}, Hann, {int(args.overlap*100)}% overlap")
    ax.grid(alpha=.25)
    fig.tight_layout()
    fig.savefig(os.path.join(args.out, "spectrum.png"), dpi=160)
    plt.close(fig)

    # --- Waterfall (spectrogram) ---
    fig, ax = plt.subplots(figsize=(11,5))
    ax.specgram(x, NFFT=args.nfft, Fs=args.fs, noverlap=int(args.nfft*args.overlap),
                cmap="magma", scale="dB")
    ax.set_xlabel("Elapsed time (s)")
    ax.set_ylabel("Baseband frequency (Hz, relative to center)")
    ax.set_title("Waterfall — relative dB, no absolute calibration")
    fig.tight_layout()
    fig.savefig(os.path.join(args.out, "waterfall.png"), dpi=160)
    plt.close(fig)

    meta = {
        "data": args.data, "fs": args.fs, "fc": args.fc, "fmt": args.fmt,
        "nfft": args.nfft, "window": "Hann", "overlap": args.overlap,
        "units": "relative dB (uncalibrated)",
        "n_samples": int(len(x)), "duration_s": len(x)/args.fs
    }
    with open(os.path.join(args.out, "analysis_meta.json"), "w") as f:
        json.dump(meta, f, indent=2)
    print(json.dumps(meta, indent=2))

if __name__ == "__main__":
    main()
Phase 4.2 — Decoding tools for NFMI and Manchester

For the 2017-style NFMI link, the likely chain is: envelope detection → threshold → Manchester decode → word/packet framing. Use multiple tools and compare.

Universal Radio Hacker (URH) 2.10.x

Investigate unknown wireless protocols; supports Manchester/PWM/PDM decoders, protocol analysis, and signal generation (generation must remain disabled for this task). URH-NG forks add optional ML-assisted modulation identification, but automated results require manual confirmation.

inspectrum

Visual analysis of large captures: amplitude, frequency, phase, IQ plots; cursors for symbol rate and period; symbol extraction. Ideal for finding Manchester transitions by eye before scripting.

GNU Radio

Build a receive-only flowgraph: File Source → Throttle → QT GUI Frequency/Waterfall Sink. Use the frequency sink’s absolute center frequency for RF-axis verification. Avoid any TX block.

Custom Python Manchester decoder

Threshold the envelope; detect mid-bit transitions; pair half-bits; validate against known preamble or frame length. A simple decoder is often more auditable than a GUI tool for a fixed protocol.

Critical boundary. URH and similar tools can transmit. For this task, use them in analysis-only mode. Disconnect or disable any TX-capable radio during decoding.

8. Phase 5 — Synthetic validation before trusting live data

Phase 5.1 — Generate complex I/Q with known tones

Requirements: one tone 50 kHz above center; a second tone 75 kHz below center, 6 dB weaker. Choose a sample rate that contains both (e.g., 2.4 MS/s). Verify frequency signs, peak locations within one FFT bin, and relative level within 1 dB. 

#!/usr/bin/env python3
import numpy as np
fs = 2_400_000
duration = 2.0
t = np.arange(int(fs*duration)) / fs
# amplitudes: 1.0 and 10^(-6/20) = 0.501187
a1, a2 = 1.0, 10**(-6/20)
x = a1*np.exp(2j*np.pi*50_000*t) + a2*np.exp(2j*np.pi*(-75_000)*t)
x += 0.001*(np.random.randn(len(t)) + 1j*np.random.randn(len(t)))
x.astype(np.complex64).tofile("synthetic_tones.cf32")
print("wrote synthetic_tones.cf32", len(x), "samples")

13. Closing boundary-condition statement

What this workflow can establish: that a receiver, antenna, capture chain, metadata sidecar, hash, FFT mapping, waterfall time axis, and Manchester decoder are working correctly on known signals; that a candidate emission exists at a given frequency and time under documented receiver settings; that a captured bitstream is consistent with a particular line code or frame length if the decode is reproducible.

What this workflow cannot establish: the presence of an implant in a person; consent or lack of consent; the identity of any operator; causation of any reported experience; the security posture of a specific implanted device; or the truth of any allegation. Those require independent clinical examination, device forensics with lawful authority, and corroborated records.

The Formalized Boundary-Condition Advisor position is therefore: measure what can be measured, label what is inferred, preserve what is original, and refuse to let an extreme narrative overwrite a null result.
